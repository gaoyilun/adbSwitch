## 原生正式版优化盘点 + P0 修复（提交 5347b47）
- 工作区在动手前是干净的（无未提交改动、无 stash、无远端），所以「先提交一版」这步实际无需提交。
- 通读 adbswitch 全部源码后，按性能/可靠性/交互/体验分级，修了 6 项 P0（详见 commit 信息）：
  1. **shell 执行超时**：RootUtil.su / ShizukuUtil.run 的 waitFor 无上限 → 一次挂起永久占死 DebugController 的**单线程 IO**，此后所有开关静默失效。改为限时等待 + destroy（RootUtil.TIMEOUT_MS=10s，CODE_TIMEOUT=-2）。Shizuku 的 IRemoteProcess 只有无参 waitFor，故挪到独立线程再 join 限时。
  2. **合并 shell 命令**：读用 `echo __ASW_USB__=$(...)` + WIFI 标记行一次取回两值；写用一条 `settings put ... ; settings put ...`；force-stop 也合并。一次开关 fork 从 6+ 降到 3。
  3. **未校准不给安全结论**：新增 `DebugController.isCalibrated()`（cachedAt!=0）；未确认时主开关摘要显示 `master_checking`「正在确认真实状态…」+ `stateUnknown` 灰点，避免 HyperOS 隐藏键导致冷启动瞬间误报「已关闭 · 可通过检测」。
  4. **AppListDialog 一次 queryIntentActivities** 替代 N 次 getLaunchIntentForPackage；下拉刷新后用搜索框当前文本重新过滤（原写死空串会清掉搜索词）。
  5. **主界面开销**：rebuildLinkageList 加内容指纹（含 privilegedAvailable）；折叠箭头图标改行内查找，删除 findViewDeep/findDeep 全树遍历（wireRowClicks 每帧都跑）。
  6. **开关单一数据源**：swLinkage/swKillBeforeOpen/swNotify 设 `persistent=false`，进入时按 cfg 回填 checked。
- 构建与自检：`gradle --offline assembleRelease` 退出码 0、日志零 `error:`；Python 字节计数确认 dex 含 `__ASW_USB__`/`; settings put global adb_wifi_enabled`/`su 执行超时`、arsc 含「正在确认真实状态…」。
- 未动手、留给用户拍板的优化项（P1/P2）：复用常驻 root shell 会话（免每次 fork）、AppListDialog 图标解码队列无取消（快滑会堆积上百任务）、磁贴点击基于可能失真的缓存决定方向、主开关行箭头 32dp 触控目标偏小（无障碍 48dp）、每次点「测试灵动焦点通知」都新建渠道、实时动态测试通知渠道未清理、swMaster 未校准时 Switch 仍按缓存显示、update 模块未启用但保留。
