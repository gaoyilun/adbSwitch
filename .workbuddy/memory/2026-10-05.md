## 启动闪退修复（ShizukuProvider exported）
- 现象：装到设备后一启动即闪退，系统直接 Killing（crashed quickly）。
- 崩溃堆栈：`java.lang.RuntimeException: Unable to get provider rikka.shizuku.ShizukuProvider` / `Caused by: java.lang.IllegalStateException: android:exported must be true`。
- 根因：`AndroidManifest.xml` 里 `rikka.shizuku.ShizukuProvider` 被显式写成 `android:exported="false"`。该 provider 是 Shizuku 管理器（不同 UID）跨进程回调传递 Binder 的入口，targetSdk>=31 时必须 `exported="true"`，否则系统拒绝实例化、进程启动即崩。
- 修复：改 `exported="false"`→`true`，并补 `android:multiprocess="false"`；`permission="moe.shizuku.manager.permission.API_V23"` 保留（仅 Shizuku 管理器可访问，更安全）。重新 `assembleRelease`（exit 0,0 error）→ `adb install -r` → 启动后进程存活、crash buffer 无 FATAL，确认闪退消除。
- 排查手法：先 `logcat -b all -c` 清全部 buffer，再 `am start`，抓 `logcat -d -b crash` + `ps` 看进程是否存活。

## 【重大】HyperOS 会向第三方 App 隐藏 adb_enabled —— 读取必须与写入同源
- 现象：Shizuku 模式下总开关状态永远错（显示关），子开关（USB/无线）因折叠在总开关下也点不到；无线调试能写、USB 看着没反应。
- 定性证据（同一时刻对比，02:19:09）：shell（uid 2000）`settings get` 读到 adb_enabled=1 / adb_wifi_enabled=1；App 用 ContentResolver 读到 **两个都 0**。即 HyperOS 对第三方 App 屏蔽了这两个键。
- 根因：DebugController 写入走 su/Shizuku shell、读取走 ContentResolver，**读写不同源**，一被 ROM 屏蔽就全错。
- 修复：读取改用与写入相同的授权通道。为避免主线程 fork 进程 ANR（历史教训），做成「缓存 + 后台校准 + 广播刷新 UI」：
  `read()` 只返回缓存（缓存空时用 ContentResolver 兜底并置 cachedAt=0 标记为未校准）；`triggerRefresh()` 在 IO 线程跑 `readViaPrivileged()`（两条 `settings get`）校准后 `broadcast()`。
  ⚠️ 坑：首次用 ContentResolver 填缓存时若把 cachedAt 设成当前时间，triggerRefresh 会误判"缓存新鲜"而**永远不校准**——必须置 0。
- 验证：`exec via shizuku: settings get global adb_enabled => code=0 out=1`，与 shell 一致，无崩溃。

## 【已修复·实装】root 能用、adb 提示未授权的真正根因 = provider 权限写错
- 用户提供对照项目 `/Users/ellen/Documents/lingxi-claw/20260906-02-01-32-971/provider-probe`（adb 模式可用）。对比两边唯一关键差异在 `AndroidManifest.xml` 的 `ShizukuProvider`：
  - provider-probe（可用）：`android:permission="android.permission.INTERACT_ACROSS_USERS_FULL"`
  - devswitch（adb 模式未授权）：`android:permission="moe.shizuku.manager.permission.API_V23"` ← 错
- 机制：`ShizukuProvider` 是 Shizuku 管理器跨 UID 回传 Binder 的入口，其 `android:permission` 决定谁能调用它。
  `moe.shizuku.manager.permission.API_V23` 是 Shizuku 管理器**签名权限**，只有管理器自己持有；
  **adb 模式下真正回传 Binder 的是 Shizuku 服务器进程（shell uid 2000），它不持有该签名权限** →
  系统拦下回传 → `Shizuku.getBinder()` 为 null、`pingBinder()` 返回 false → `available()` 为假 → 显示「未授权」。
  **root 模式服务器跑 uid 0 绕过权限检查** → 回传成功 → 正常。这精确解释了「root 能用、adb 不能」的对称性。
- 修复：`ShizukuProvider` 的 `android:permission` 改为 `android.permission.INTERACT_ACROSS_USERS_FULL`（Shizuku 官方模板，adb 模式服务器持有）。
  `moe.shizuku.manager.permission.API_V23` 保留为 `<uses-permission>` 运行时权限声明（正确，不可删）。
- 构建：`gradle-8.13 --offline assembleRelease`（BUILD SUCCESSFUL 26s）。
