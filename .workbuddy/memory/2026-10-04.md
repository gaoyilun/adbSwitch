## Live Updates（实时动态）修复：常驻通知退化成普通通知
- **现象**：「实时动态测试」通知是 Live Update（状态栏胶囊/锁屏），但真正关调试后发的常驻通知
  只是普通通知。
- **排查**：`git log -S` 显示 `UsbToggleService.java` 自首个 commit `05ca808` 起就没再改过，
  Live Updates 相关代码（`setRequestPromotedOngoing` 反射）一直都在，不是被改坏的。
- **根因**：`buildNotification()`（常驻）与 `sendLiveUpdateTest()`（测试）都调了
  `setRequestPromotedOngoing(true)`，但**常驻那条没设 `setOngoing(true)`**，只有测试那条设了。
  Live Update 提升以「ongoing 通知」为前提；常驻走 `startForeground` 且 FGS 类型为
  `FOREGROUND_SERVICE_TYPE_SPECIAL_USE`，不被提升 → 只有测试能提升。
- **修正**：`buildNotification()` 补 `.setOngoing(true)`，与测试通知对齐。
- **不加「取消置顶」按钮**：用户明确要求不要（实测该通知可滑动划掉）。已移除。
  常驻通知在调试被恢复打开时由 `stateReceiver` 自动 `stopSelf()` 撤掉。

## 调研：主功能能否用 Shizuku 替代 su（用户本轮提问）
- 结论：**可以，且无需 root**。项目全部 su 依赖只有 3 处写入口（均在 `DebugController`）：
  ① `settings put global adb_enabled` ② `settings put global adb_wifi_enabled`
  ③ `am force-stop <pkg>`（开调试前杀联动应用）；外加 `RootUtil.hasRoot()` 探测（非动作）。
- 原理：Shizuku 经 adb 启动即以 shell uid 2000 运行，等价于 `adb shell`，
  `settings`/`am` 是 shell 可写操作，`Settings.Global` 写受 shell/root 放行；读状态（`Settings.Global.getInt`）本就零权限不变。
- 最小改造：`RootUtil.su(cmd)` 换成 `Shizuku.newProcess(new String[]{"sh","-c",cmd},null,null)`，
  或走 UserService 以 shell uid 直接 `Settings.Global.putInt`；`hasRoot()` → `Shizuku.pingBinder() && checkSelfPermission()==GRANTED`。
- 代价：非 root 设备 Shizuku 经 adb 启动**重启后失效需重授权**（root 模式才保活）。
  若经「无线调试」启动 Shizuku，本 App 又把无线调试关掉，部分 ROM 可能连带杀掉 Shizuku 进程（自指死锁），
  故推荐经 USB adb 一次性 `start.sh` 或 root 模式启动。
- 其余功能（QS 磁贴、常驻通知、动态/桌面快捷方式、App 选择、Live Updates、ContentObserver）全不依赖 su，零改动。
