## 调研（未改代码）：能否用 root / Shizuku 关闭「开发者选项」
- 结论：可行，且成本极低——复用现有 `settings put global` 通道即可，键为 `development_settings_enabled`（AOSP `Settings.Global.DEVELOPMENT_SETTINGS_ENABLED`）。
- 实测（2510DRK44C，Android 17 / API 37，KernelSU root，Shizuku 以 uid 0 运行）：
  - `settings get global development_settings_enabled` = 1；global 表里无 MIUI 私有开发者选项键。
  - uid 2000（`su 2000`）写该键 rc=0；写一个不存在的键 `zzz_asw_probe` 也成功 → 该环境 uid 2000 对 global 表无键级白名单限制（dumpsys 显示 com.android.shell 的 `WRITE_SECURE_SETTINGS: granted=true`）。
  - AOSP SettingsProvider（android13-release，frameworks/base/packages/SettingsProvider）行 2032-2039：「System/root/shell can mutate whatever secure settings they want」。
  - 注意：本机 adb shell 直接是 uid 0（context u:r:ksu:s0），`runcon u:r:shell:s0` 被 SELinux 拒（rc=126），故「纯 adb 启动 Shizuku（uid 2000 + shell context）」未能在本机完整复现，跨 ROM 仍需实机确认。
- 语义（AOSP SettingsLib `DevelopmentSettingsEnabler`，android10-release）：设置里的开发者选项主开关 = 只写 `development_settings_enabled`，**不会**联动 `adb_enabled`。因此命令行改此键 = 与 UI 开关等价；「开发者选项关 + USB 调试仍开」是合法状态。
- HyperOS 遵循 AOSP：Settings.apk（/system_ext/priv-app/Settings）的 dex 中确实含 `development_settings_enabled` 字符串。
- 不可行的替代：`UserManager.DISALLOW_DEBUGGING_FEATURES` 需 Device Owner/Profile Owner，`dumpsys device_policy` 显示 Device Owner Type: -1；root 也不能直接设（`dpm set-device-owner` 代价过高），不推荐。
- 风险点（待用户定夺）：关掉后设置入口消失，恢复需连点版本号 7 次；若与 adb 开关不联动，会出现「UI 找不到 USB 调试开关但 adb 还在」的 UX 陷阱。

## 实现：开发者选项独立开关（调研结论落地）
- 形态（用户定稿）：独立开关，放在无线调试下方，**不与主开关联动、不参与折叠**（始终显示），样式/逻辑对齐 USB / 无线两个子开关（pref_row_state 行 + stateIcon 指示灯 + 未授权置灰 + 启动窗口期点不动）。
- `DebugController`：新增 `KEY_DEV="development_settings_enabled"`、`EXTRA_DEV`、`LAST_DEV`、`TAG_DEV_OUT`；`State` 变成三字段（usb/wireless/**dev**），`anyOn/allOff` **不含 dev**（主开关语义不变）；`readViaPrivileged` 一条 shell 读三个键，**dev 读不到时降级为 false 并记日志**（个别 ROM 无此键不能把主功能拖死，usb/wireless 仍严格要求 0/1）；新增 `writeDev`/`setDev`/`toggleDev`（不调 killQuickApps —— 它不影响 adbd）；`loadSaved` 的 dev 恒 false（一键打开不得偷偷开回开发者选项）。
- `prefs.xml`：`swDevOpts`（order=30）在 swWireless(20) 之后；catDebug 下各行都写死 `android:order`（master 0 / usb 10 / wireless 20 / dev 30 / auth 40）。
- **顺序坑（重要）**：MainActivity 里对 catDebug 调 `setOrderingAsAdded(false)`。否则折叠后再展开时 `addPreference(swUsb/swWireless)` 会把它们追加到分类末尾，排到开发者选项行之后。
- `State` 构造变三参，同步改了 4 处：MainActivity 广播接收、AdbTileService 广播接收、AdbToggleService 广播接收 + onStartCommand 的乐观态（dev 传 false）。
- 新开关**未加** `android:persistent="false"`：为与 usb / wireless 两个状态型开关完全一致（二者也没加，值一律由 refresh 按真值回填）。
- 未做（用户没要求）：dev 的桌面快捷方式 / 磁贴 / 通知联动；README 未更新。

## 修复「授权模式切换 × 开关状态」链路 bug + 清理调试端点（22:45–22:56）

- 用户报 bug：root 已授权全开 → 切未授权 Shizuku → 子开关灰但主开关仍可拨 → 关主开关后无法再开 → 切回 root 有几率卡在关闭态。
- **根因（四个叠加）**：
  1. `DebugController.setMasterBlocking` 写失败时 `after` 兜底成 `new State(false,false,false)` 并无条件进 cache+persistLast → **「假全关」污染内存缓存与跨启动 LAST_***（关了开不回、切回 root 后 UI 卡在污染值且校准被节流挡住）；
  2. `MasterSwitchPreference` 的 Switch widget enabled 只看 known、不跟随 `Preference.isEnabled()` → `applyRootState` 置灰被直接拨 Switch 绕过（整行点击禁用但 widget 没禁）；
  3. 子开关写模板对 `w.after==null` 不拒绝提交（同源）；
  4. `chooseAuthMode` 切模式后不作废状态缓存（换通道后旧缓存照用 + 1500ms 节流可能吞掉重校准）。
- **修复**：① setMasterBlocking `after==null` → 拒绝提交、广播未污染缓存、cb(false)；新增 `finishSubWrite` 统一六处子开关收尾（同规则）；`commitAfter` 改为提交+广播+返回状态。② MasterSwitchPreference 加 `prefEnabled` 镜像 + 覆写 `setEnabled` 同步 widget，widget enabled=known&&isEnabled()（绑定/applyState/setEnabled 三处合成）。③ chooseAuthMode 的 setMode 后加 `DebugController.invalidateAndRefresh`（at 置 0 绕节流）。④ applyMasterState 补「退出码 0 但真值没变」→ toast_write_not_effective（P1 遗留第四处）；runLinkage 失败分支补 privilegedAvailable=false+applyRootState（三主开关写路径行为统一）。
- **清理（用户点名）**：删两个 adb 调试入口（`ACTION_DEBUG_PICKER`/`ACTION_DEBUG_MASTER`+`EXTRA_MASTER_ON` 及处理块）；删 openAppPicker 两处 Log.i、`getInt` 每次回读 Log.i；`runPrivileged` 长日志（cmd/out/err 全文）降 Log.d 只留 code/ok；删无调用方死代码 `toggleDev`。
